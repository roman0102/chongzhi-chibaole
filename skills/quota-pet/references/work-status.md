# 真实工作状态

`codex_work_status.py` 订阅正在运行的 Codex 桌面端状态。当前实现使用 Windows 本地命名管道兼容协议，已核对桌面版本 26.1021.3705.0；它不是公开稳定的 app-server API。桌面未运行、聊天没有可用的桌面 owner、协议无法识别或连接失效时，显示“工作状态未连接”，不能推断任务已完成。其他系统的工作状态源尚未实现。

## 使用与验收

桌宠启动时自动连接。默认 `--work-scope desktop` 汇总可发现的本地桌面聊天；`--work-scope thread` 只跟随启动聊天，默认从环境 `CODEX_THREAD_ID` 取得 ID，也可用 `--work-thread` 指定。此 ID 是运行参数，不应硬编码进分享包。

用 `python scripts/codex_work_status.py --scope desktop --seconds 10` 单独检查连接。输出仅含状态、连接事实、计数和观测时间。之后启动桌宠，检查 readiness 的 `work_connected`、`work_state`，以及悬停卡的实际内容。等待、失败和完成的边界用合成快照验证，不为演示而发起真实模型任务或审批请求。

桌面发现只查询本地状态库中最近 50 个未归档聊天 ID，再向桌面询问 owner 并只读跟随。每 10 秒发现新聊天，已跟随的聊天继续订阅，每 30 秒确认 owner 仍然有效。聚合优先级为等待处理、出错、工作中、完成、空闲。它只覆盖本机桌面能够提供状态的聊天，不代表远程或云端全部任务。

## 状态与动作

以下动作对应l2m_serinorin或实现了相应动作的图片皮肤。默认小猪只显示工作状态点和卡片，并随状态漫游或暂停。

| 状态 | 动作 |
|---|---|
| working | 走路；悬停时原地继续工作动画 |
| waiting | 停下来招手；提示等待批准、回复或其他处理 |
| completed | 短暂开心，然后待机；同一事件不反复播放 |
| error | 短暂哭泣，然后待机并保留出错状态 |
| idle | 自由溜达或休息 |
| unknown | 静止和灰色状态点 |

额度只选择胖瘦形态，不能用额度高低判断工作是否成功。完成状态包括桌面标为未读的既有完成记录，以及刚观察到的任务结束；用户中断不会被当作成功。菜单中的动作试玩有短暂标识，不改变真实额度或工作状态；结束后自动恢复。

## 数据边界

订阅只发送初始化、owner 发现、跟随与退订消息，不成为 owner，不回答审批，不开始、恢复或中断任务。连接和关闭不修改桌面配置，也不安装 hook。

桌面初始协议会发送一次会话快照。连接器瞬时解码后只保留 runtime 状态、等待类型、turn 状态、睡眠标记和关联索引；聊天正文、工具参数和结果立即丢弃。后续只应用状态字段补丁，其余丢弃。不把原始快照写入文件、日志或 UI。故障消息使用固定文本，不能把协议原文或异常载荷输出。

单帧上限按当前桌面协议为 256 MiB。长聊天首次快照可能造成较高瞬时内存占用，随后释放；不能把稳定运行时的占用冒充初始化峰值。已做一组本机长历史测试：状态观察器约 637 MiB 瞬时峰值、约 75 MiB 稳定工作集；这是特定数据量下的结果，实际随聊天长度变化。持续监听不轮询完整历史。

供其他来源接入时，可通过 `--work-status-file` 传入本地 JSON：`state`、`connected`、`observed_at`（Unix 秒）、可选 `detail_kind`、各状态 `counts`、`source`、`event_id`。文件超过 30 秒或格式无效时转未知。正常运行优先直接内存回调，不需要把持续状态写入磁盘。

公开文档说明 app-server 的运行状态与 turn 事件，但独立新开的 server 无法自动观察桌面已有连接：[官方 app-server 文档](https://learn.chatgpt.com/docs/app-server)。兼容层变化时先核对本机实际协议，不能改为猜测状态或读取凭据。
